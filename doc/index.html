Diseño con límites claros

Patrones, sin etiquetas vacías.

DDD, Clean Architecture y hexagonal son lentes útiles; la documentación separa lo que existe hoy de lo que sería una evolución futura.

01 / DOMAIN

DDD pragmático

Módulos organizados por capacidades, handlers y eventos donde aportan valor. El modelo ORM todavía participa en varias áreas.

02 / APPLICATION

CQRS selectivo

Command y query buses separan algunos casos de uso; no todos los endpoints pasan por ellos ni es event sourcing.

03 / ADAPTERS

Hexagonal parcial

Routers, servicios, repositorios y motor OCR ofrecen fronteras prácticas; no todos los puertos están formalizados.

04 / RELIABILITY

Outbox e Inbox

Eventos durables, consumo idempotente y reintentos con backoff sin depender de un broker externo.

05 / OCR PIPELINE

Procesamiento adaptable

Texto PDF primero, OCR cuando hace falta; motores PaddleOCR, Tesseract o stub de pruebas.

06 / OPERATIONS

Operable por contenedores

FastAPI, workers, PostgreSQL, SPA y Nginx; con métricas, logs estructurados y controles de seguridad.
