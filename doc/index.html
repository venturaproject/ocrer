Clear boundaries, pragmatic design

Patterns, not empty labels.

DDD, Clean Architecture, and Hexagonal Architecture are useful lenses. The docs distinguish what exists today from possible future evolution.

01 / DOMAIN

Pragmatic DDD

Capability-oriented modules, handlers, and domain events where useful. ORM models still participate in several areas.

02 / APPLICATION

Selective CQRS

Command and query buses separate some use cases; not every endpoint uses them, and this is not event sourcing.

03 / ADAPTERS

Partial Hexagonal Architecture

Routers, services, repositories, and the OCR engine provide practical boundaries; not all ports are formalized.

04 / RELIABILITY

Outbox and Inbox

Durable events, idempotent consumption, and backoff retries without requiring an external broker.

05 / OCR PIPELINE

Flexible processing

Read PDF text first and run OCR when needed; supports PaddleOCR, Tesseract, or a test stub.

06 / OPERATIONS

Container-ready

FastAPI, workers, PostgreSQL, SPA, and Nginx, with metrics, structured logs, and security controls.
